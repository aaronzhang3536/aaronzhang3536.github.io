# 手机后端接入：现有用户数据清单

> **2026-10-18 接入更新：** 本文以下内容保留为 `9ff518ce` 时的字段盘点基线；其中“未接入”“拟支持”“尚需实现”描述的是接入前状态。现已接入的账号、数据接口、全站隔离、备份与验证，以 [当前接入文档](phone-backend-integration.md) 和 [实际验证记录](phone-backend-verification.md) 为准。

核对日期：2026-10-18。依据为本仓库当前源码；字段名称反映已有客户端存储，后文的服务端建模与合并建议尚未实现。

## 1. 应用标识与当前边界

建议沿用 [package.json](../package.json) 中已有的英文名称 **`within-one-frame`** 作为 `APP_ID`，避免再引入一套名称。这个建议不代表已在手机后端注册应用，也不代表专属子域名已配置。

当前 [cloudsync.js](../src/scripts/lang/cloudsync.js) 的默认服务仍为 `https://yzzn-sync-lzgf3t47.edgeone.dev`。只有外语中心的学习数据进入现有同步流程；书签、音乐、术数历史、游戏厅与 Babel 手册均未因此获得云端保存能力。现有 `yzzn-cloud-api` 覆盖仅在 localhost 开发环境生效，正式站点的可配置手机 API 入口仍需实现。

这份清单用于确定要迁移的内容及语义，不能替代手机 Django 的真实账号接口文档，也不能作为数据库迁移、权限隔离、真实 CRUD 或重启持久化已验证的证明。

## 2. 外语中心：英语与另外七种语言

来源：[english.js](../src/scripts/lang/english.js)、[eastasian.js](../src/scripts/lang/eastasian.js)、[synccore.js](../src/scripts/lang/synccore.js)、[langdata.js](../src/scripts/lang/langdata.js)。下列值均按 JSON 存入 `localStorage`。

### 2.1 英语

| 当前键 | 已有内容与字段 | 当前保存范围 | 接入时应保留的操作与合并语义 |
| --- | --- | --- | --- |
| `yzzn-en-words` | 词条数组：`w` 单词、`def` 释义、`t` 添加时间、`mt` 修改时间；可选 `ph` 音标、`lv` 词库等级；可选 `srs: {ef, n, i, d}` 分别表示易度、重复次数、间隔天数、到期时间 | 本机；登录后参与现有 EdgeOne 同步 | 增加、读取、复习更新、删除单词、清空词本。词条身份按 `w.toLowerCase()`；同一词条按修改时间选择整条最新记录，不能只挑最大的复习间隔，否则“忘记后重学”会丢失 |
| `yzzn-en-stats` | `{YYYY-MM-DD: count}`，日期对应复习计数 | 同上 | 按日期累加本次新增量；现实现有基线时使用三方合并，不能简单取两台设备最大值 |
| `yzzn-en-daily` | `{YYYY-MM-DD: count}`，每日新词领取数量 | 同上 | 当前按数值取大，用于新词额度；它不是 `en-stats` 的复习次数，不能直接套用复习计数累加规则 |
| `yzzn-en-game` | `{sourceId: {stars: {stage: number}, exempt: {stage: boolean}, placed: boolean}}`；词库来源分别保存星级、豁免关卡和已定级标记 | 同上 | 同一关卡星级取大；现有豁免与定级标记按布尔“或”合并。重置须有独立清空语义，不能仅写空对象后期待合并自动删除 |

时间字段 `t`、`mt`、`srs.d` 当前使用 JavaScript 毫秒时间戳。日期计数以 `localDay()` 生成本地日历日期，已有 UTC 日期存档兼容逻辑；迁移不能把日期键按服务器时区重新解释后挪到前一天或后一天。

### 2.2 日、韩、法、德、西、意、俄

本节 `<lang>` 对应 `ja`、`ko`、`fr`、`de`、`es`、`it`、`ru`，共七种语言；与英语合计八种。

| 当前键 | 已有内容与字段 | 当前保存范围 | 接入时应保留的操作与合并语义 |
| --- | --- | --- | --- |
| `yzzn-<lang>-words` | 词条数组：`{w, r, rom, def, due, iv, ef, rep, mt, f?}`；`r` 为读音或语言相关词性信息，`rom` 为转写，`f` 可为带冠词的展示形式；`due` 到期毫秒时间戳、`iv` 间隔天数、`ef` 易度、`rep` 重复次数 | 本机；登录后参与现有 EdgeOne 同步 | 增删改查及清空；按原文 `w` 区分词条，不能照搬英语统一转小写；同一词条按修改时间选择完整最新状态 |
| `yzzn-<lang>-dojo` | `{"setId:itemText": [rightCount, wrongCount]}`；实际对象键由 `dojoSet + ':' + item` 拼接 | 同上 | 对、错两个计数独立累加；不能把数组当集合去重。服务端建模宜拆开 `set_id`、`item_id`，避免仅靠字符串分隔符推断结构 |
| `yzzn-<lang>-daily` | `{YYYY-MM-DD: reviewCount}` | 同上 | 复习计数使用三方累加；含义与英语 `en-daily` 不同 |
| `yzzn-<lang>-game` | `{stars: {stage: number}, arenaBest?: number}` | 同上 | 关卡星数、竞技场最佳成绩取大；清空进度须传播重置记录 |

### 2.3 现有合并元数据

`yzzn-sync-meta` 的形状为 `{del: {storageKey: {entryId: deletedAt}}, wipe: {storageKey: clearedAt}}`。它随同步作为删除与清空元数据处理，不是可展示的学习内容。

当前合并器会去除删除时间不早于词条修改时间的词条，并传播整键清空；删除墓碑保留 180 天，每个键最多保留 3,000 个。因此长期离线设备重新上线前必须考虑旧数据复活问题，迁移后应明确服务端墓碑保留期和过旧客户端的重新同步规则。

现有计数器在有公共基线时按 `max(local, remote, local + remote - base)` 合并；首次同步、缺基线等情形退化为取大以避免重复累计。基线及未确认写入必须与对应用户、应用、后端绑定。服务端若改为操作式 API，可使用唯一操作 ID 去重；不能在请求结果未知时直接再次增加同一笔计数。

白名单检查目前是语言键前缀规则，并排除 `*-cfg`、`yzzn-en-ai`、`yzzn-en-dict`。未来业务接口应对上述具体数据类别、字段类型、长度和数量分别校验，不能接受任意客户端 `localStorage` 键。

## 6. Babel 生词手册

来源：[game.js](../public/standalone/babel/game.js)、[ui.js](../public/standalone/babel/ui.js)。

`babel-manual` 是本机 JSON 对象：`{lowercaseWord: star}`，星级为 `0` 至 `3`，缺项等同于未学习。常规学习只提升星级，因此同一词的正常进度可以取大；“重置生词手册”会写成空对象，云端接入必须增加清空代际或清空时间，否则旧设备会把已重置的星级带回来。

拟支持手册列表、更新词条星级和重置。词义来源于静态词库，不是该存档里额外保存的一份用户文本。当前牌组、战斗、地图、血量等单局状态存在 `G.state` 内存中；本次接入不能默认为这些状态新增云存档。

## 7. Extras 游戏与站点偏好

来源：[site.js](../src/scripts/site.js)。本节所有存储目前均为设备本地，未被现有语言同步上传。

### 7.1 成绩与累计次数

成绩通常以十进制数字文本存储。未来应将 `game_id`、难度或尺寸、`metric`、数值、单位和重置状态分开建模，不能把所有数值统一按“越大越好”合并。

| 当前键或后缀 | 含义 | 拟采用的合并规则 |
| --- | --- | --- |
| `yzzn-fish` | 点按“摸鱼”的累计次数，不是整座鱼缸状态 | 累计新增操作，需幂等；有旧基线时可三方合并，不能重复上传同一增量 |
| `yzzn-arc-coins` | 游戏厅累计投币／启动次数 | 同上；当前不是付费货币、可消费余额或资产账户 |
| `yzzn-arcade-hi` | 能量收集站最高纪录 | 最大值 |
| `yzzn-arc-{snake,tetris,breakout,invaders,asteroids,flappy,dino,bug,typer,tex2048,nback,simon,overfit,frustum}` | 各游戏最高成绩；`nback` 为正确率百分比，`simon` 为最长序列等 | 按游戏分别取大；不同指标不互相合并 |
| `yzzn-arc-rhythm` | 节奏机普通难度最高分 | 最大值 |
| `yzzn-arc-rhythm-{easy,hard,hell}` | 节奏机其余三档难度最高分 | 按难度分别取大；普通档没有 `-normal` 后缀 |
| `yzzn-arc-mines`、`yzzn-arc-slide15`、`yzzn-arc-maze` | 最佳完成时间，秒 | 最小有效正值；当前 `0` 表示无纪录，不能赢过已有成绩 |
| `yzzn-arc-memory`、`yzzn-arc-grad` | 最佳完成步数 | 最小有效正值 |
| `yzzn-arc-reaction` | 反应测试平均用时，毫秒 | 最小有效正值 |
| `yzzn-arc-tuner` | 调音误差纪录，音分 | 沿用当前有效纪录语义，越小越好；须区分未记录与有效零误差，不能在新模型中永久以 `0` 兼任两者 |
| `yzzn-arc-jig2` 至 `yzzn-arc-jig20` | 对应 `2×2` 至 `20×20` 拼图尺寸的最佳时间，秒 | 按尺寸分别取最小有效正值 |

删除或重置任一最高／最低纪录时都需要传播重置状态。只从云端删除记录，再与其他设备旧最高分取大或旧最短时间取小，会让该纪录重新出现。游戏运行中状态、拼图图片和浏览器生成音频目前未作为这些存档保存。

## 8. 评论：已有独立的 GitHub 身份与数据来源

来源：[comments.js](../src/scripts/comments.js)、[文章页面](../src/pages/posts/[id].astro)。

当前评论由 giscus 接入本仓库的 GitHub Discussions，使用 `Announcements` 分类、按页面 `pathname` 映射，并开启 reactions。评论已在 GitHub 上持久化，不在本地存储清单中，也不受语言账号登录控制。

如果后续将评论改接公共手机账号，应独立设计文章评论接口和迁移过程。候选字段包括 `article_id`、`parent_id`、`body`、服务端作者 ID、创建／修改时间、可见状态；如保留 reactions，还需要反应类型及用户关系。评论编辑、删除和管理权限须分别校验作者与管理角色。

旧评论归属于 GitHub 用户。不能因为 GitHub 用户名与公共账号用户名相同，就允许公共账号修改旧评论；需要经过验证的身份绑定，或保留明确的旧来源作者及只读记录。导入记录应保留原讨论／评论 ID，保证重复导入不生成副本。当前变更没有迁移评论，也没有替换 giscus。

| `yzzn-cloud` | `{token, u, uid, lastSync, owner, ownerName, dev}` 等登录与归属状态 | 不能当业务存档上传或导出。令牌仅用于规定的认证请求；设备标识仅按真实账号接口的会话用途使用，不能复制进普通数据表 |
| `yzzn-cloud-api` | localhost 开发用接口覆盖 | 是连接配置，不是用户业务数据；不能从不可信同步记录加载后端地址 |
| `yzzn-cloud-base` | `{uid, v, keys, pv?, pkeys?}`，公共合并基线与未确认写入 | 仅供当前客户端重试和合并，不能当成另一个用户的数据源或普通业务记录上传／导出 |
| `yzzn-cloud-recovery` | 客户端批量落盘失败时使用的恢复记录，绑定用户归属与接口，保存业务键／基线写入前后值、正在恢复的键及必要的同步时间状态 | 不自动上传或导出，不复制令牌。它可能含学习数据，仍须按本地用户归属保护；换账号不能把旧日志恢复到新账号数据中 |

现有语言导出会额外包含配置中非机密字段，并过滤名称含 `key`、`token`、`secret`、`pass` 的字段。导出白名单与云端同步白名单不是同一概念，新的业务接口应使用明确字段定义。

## 10. 服务端模型与客户端隔离仍需实现

以下为实现约束，未表示数据表、接口或管理入口已存在：

1. 复用经过核对的现有公共账号身份；业务请求通过 `Authorization: Bearer <token>` 认证。服务端解析身份并校验应用授权，不能相信请求体中的 `user_id` 或只凭客户端传来的 `app_id` 决定归属。
2. 各资源必须同时绑定应用和用户。可为业务模型增加受服务端控制的 `application`、`owner`，并按资源定义逻辑主键、版本和删除状态；书签、词条、历史、偏好、成绩、累计操作分别校验字段。`APP_ID` 是公开标识，不是访问密钥。
3. 查询、单条详情、创建、更新、删除、批量同步、导入导出和管理入口都必须使用同样的用户／应用范围。直接提交另一个用户的记录 ID、另一应用 ID 或批量中的混合归属记录，也不能越权。
4. 客户端持久空间应按后端来源、`APP_ID` 和服务端用户 ID 分开，包括业务缓存、合并基线、待发送操作、恢复日志及账户相关配置；访客数据应有独立空间和明确的一次性导入流程。
5. 登录切换和退出时，页面内存也应随身份重新载入；暂停或取消旧请求，阻止旧请求结果写进新身份。未确认的网络写入应在恢复后核对状态，再进行幂等重试。
6. 不同应用可以复用公共账号，但是否共用会话、是否支持刷新、退出是否影响其他应用、令牌如何绑定应用，都要以真实账号接口和服务端能力为依据。

**当前仍存在全站共享本地键，退出保留本机数据，旧客户端也有经用户确认后合并本机数据到另一账号的流程。** 对同步会话与本地保存失败的修复不等于完成上述全站命名空间、服务端数据隔离或应用授权。`yzzn-en-cfg.key` 也仍是本地共享配置，需要在最终账号空间设计中一并处理。

已有 EdgeOne 用户 ID 与后续公共账号用户 ID 不能直接视为同一身份，用户名相同也不能证明数据归属。跨后端迁移应使用经过验证的旧账号会话或由本人发起的明确导入，记录来源和迁移状态，并保证重复执行可识别。

## 11. 与本清单对应的验收点

此处列出待完成验收，不是实际测试通过记录；实际执行结果应单独记录环境、版本和观察到的返回值。

| 验收内容 | 应验证的具体行为 |
| --- | --- |
| 真实账号契约 | 注册、登录、当前用户、退出、令牌过期、多应用会话行为符合现有后端文档 |
| 真实数据 CRUD | 至少验证词条、可取消的书签／任务、最佳纪录、累计计数、历史与重置；服务器读取结果与客户端一致 |
| 数据隔离 | 两个真实用户和两个应用交叉尝试列表、详情、增改删与批量接口；不能读取或修改另一归属的数据 |
| 重试与断网 | 服务端已保存但客户端未收到响应、存储配额不足、重连及换账号期间晚到响应，均不会误报成功、重复计数或串数据 |
| 删除与合并 | 删除词条、取消收藏、取消计划、清空手册、重置游戏纪录后，旧设备同步不会把数据带回 |
| 编码与指标 | 原始文本和 JSON 按各自格式回写；最快时间取小、最高分取大、偏好可调低；节奏成绩字段来自同一次记录 |
| 持久化与部署 | 先完成数据库及配置备份，再运行迁移；真实服务重启后读取先前写入的数据，并记录 HTTPS、跨域和域名配置的实测结果 |
| 排除项 | 业务请求体与管理入口不出现 AI Key、令牌、设备校准、天气缓存、出生信息或新采集的聊天内容 |

实现和验证记录应继续使用本仓库的 [ARCHITECTURE.md](../ARCHITECTURE.md) 与相关接口文档维护，避免把“已盘点”“客户端已修复”“服务端已部署”混写为同一种完成状态。
